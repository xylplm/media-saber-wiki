# 通用规范

## 交流语言（最高优先级）

- **始终用中文回复用户**：包括最终回答、中间过程说明、进度提示、总结、提问等
- 代码注释、设计文档、需求文档、commit message 也尽量用中文
- 例外：代码标识符（变量/函数/类名）、第三方库术语、命令行命令本身保持英文
- 即使用户用英文提问，也用中文回答

## Git 提交信息

- 除非用户明确要求，否则不要新建分支；提交代码时直接在当前分支 commit
- **推荐用中文写普通提交信息**，格式：`<type> <emoji>: <subject>`
- **一句话言简意赅**：多项内容用逗号并列；**禁止用「——」破折号连接的解释长句**，用户能懂即止（提交摘要会进更新日志给用户看）
- 采用语义化祈使语气，包含模块名称，类型与 emoji 对应关系：
  - `feat ✨`：新功能
  - `add ➕`：新增文件或内容
  - `fix 🐛`：最终修复；进行中或部分修复用 `to:` 标明
  - `docs 📚`：文档变更
  - `merge 🔀`：分支合并
  - `deps 📦`：依赖变更
  - `build 🏗️`：构建系统变更
  - `perf ⚡`：性能优化
  - `refactor 🔁`：仅重构，无行为变更
  - `chore 🔧`：仅工具或配置变更
- 示例：`feat ✨: 首页增加豆瓣电影正在热映小部件`

## 代码注释

- 函数/方法：1-2 行描述 + 必要的参数说明，不写设计理由散文
- 字段定义：行尾 1 行注释说明用途
- 禁止：多段 task/requirement/property 引用、review 标记、注册策略论述
- 类级注释最多 3-4 行描述职责

## 代码质量

- 拒绝冗余代码：不创建只有一个消费方的中间层/适配层
- 拒绝死代码：未使用的 import、变量、方法及时删除
- 常量/类型定义能放在同一文件就不拆文件
- 有限集合值用常量定义，不用裸字符串
- 用户体验优先，保证维护性，可扩展性，不过度设计，不冗余设计

## 面向用户的文案

- 不暴露英文字段名给用户（不写括号注解如 `名称（name）`）
- tooltip 用纯中文描述功能含义
- 使用项目主题化命名：天序/拨序/心头好/灵识搜术/秘术流派/未归宗/风云榜/梦萦阁/万灵阁/履道录/秘术鉴/解封/封印/启灵/分神/归墟/梦萦/断缘/造物主/弟子数

## 完成标准

- 前端 `tsc --noEmit` 通过
- 后端 `go build ./...` 通过
- 涉及 `.api` + `types.go` + 业务代码时三处必须同步

## Shell / 终端命令

- 用户的 shell 可能是 Git Bash 或 PowerShell（视进程而定），不要混用语法
- 禁止：`Get-Content` / `Get-ChildItem` / `.Length` / `.Count` 等 PowerShell 独有语法
- 禁止：`tail -n` / `head -n` 与管道（`|`）配合（PowerShell 没有这些命令）
- 文件读取用 `read_file` / `read_files`，不要 `cat` / `Get-Content`
- 文件搜索用 `grep_search` / `file_search`
- 列目录用 `list_directory`
- 必须 shell 时（`git` / `go build` / `flutter analyze` 等）尽量写 shell 无关的命令；查看大输出靠工具的 `skipPruning` 截取
