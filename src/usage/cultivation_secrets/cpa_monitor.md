# 🔍 CPA 监控

定时巡检 CPA（Cloud Provider Authenticator）中已启用的认证文件，自动刷新额度并检测异常账号，支持自动删除 401 异常的认证文件。

## ⚙️ 功能特点

- 批量检查 CPA 认证文件的有效性
- 自动刷新账号额度信息
- 401 异常账号可自动删除对应认证文件
- 支持按提供商筛选检查范围
- 支持并发检查，提升巡检效率

## 🚀 配置指南

| 参数 | 必填 | 说明 |
|------|------|------|
| BaseURL | **是** | CPA 管理 API 根地址，填写到 `/v0` 层，例如 `http://127.0.0.1:8317/v0` |
| Token | **是** | CPA 管理 API 的 Bearer Token（即登录密码） |
| 检查周期 | 否 | Cron 表达式，留空则仅支持手动运行，例如 `0 * * * *`（每小时） |
| 提供商 | 否 | 选择要检查的提供商（Codex / Antigravity / Gemini / Gemini CLI / Claude / Qwen），留空检查全部 |
| 并发数 | 否 | 批量检查时的并发 worker 数，默认 10 |
| 通知开关 | 否 | 开启后每次运行结束推送一条汇总通知 |
| 账号异常自动删除 | 否 | 开启后，401 异常账号会自动删除对应认证文件 |

### 🔧 工具栏操作

- **运行一次**：立即执行一次全量巡检

## 📖 使用说明

1. 确保 CPA 服务已部署并正常运行；
2. 在本插件中填写 CPA 的 BaseURL 和 Token；
3. 根据需要选择要检查的提供商，或留空检查全部；
4. 首次建议手动「运行一次」确认连接正常；
5. 确认无误后设置检查周期实现自动巡检。

## ⚠️ 注意事项

- 开启「账号异常自动删除」前请确认理解其行为：401 状态的认证文件会被直接删除，不可恢复；
- BaseURL 必须填写到 `/v0` 这一层，不要多加或少加路径；
- 并发数不宜设置过高，避免对 CPA 服务造成压力。
