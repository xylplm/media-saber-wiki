# 🔍 strm 媒体信息探测

**strm 媒体信息探测** 插件扫描本地 strm 文件指向的网盘媒体，使用 ffprobe 读取真实的音轨 / 字幕流信息并落库，供媒体代理在 Plex / Emby / Jellyfin 播放 strm 时注入真实媒体信息，实现播放时切换音轨、字幕。

## ⚙️ 功能特点

- 扫描 strm 文件，解析内容身份（hashType + fileHash），对网盘直链执行 ffprobe 读取真实流信息
- 可先同步媒体服务器已有的分析结果（Plex / Emby / Jellyfin），ffprobe 只补缺口，节省网盘流量
- 已有成功数据不重复探测，失败的文件在重试间隔内自动跳过（负缓存）
- 支持备份数据、导入还原与分享下载（按内容 hash 跨实例复用）
- 支持定时探测与完成消息推送

## 🚀 配置指南

| 参数 | 必填 | 说明 |
|------|------|------|
| 扫描目录 | 否 | strm 文件所在的本地目录，每行一个，递归扫描 `.strm` 文件；留空则跳过扫描（开启同步时仅同步媒体服务器数据） |
| 定时探测 | 否 | 标准 5 段 Cron，定时执行一轮探测（含可选的服务器数据同步）；留空不自动执行 |
| 同步媒体服务器数据 | 否 | 探测前先从已启用的 Plex / Emby / Jellyfin 拉取其已分析出的媒体流信息（如 Emby 神医对 strm 的分析），服务器没有的才用 ffprobe 补 |
| 同步目标（媒体服务器 → 媒体库） | 否 | 添加分组限定参与同步的媒体服务器与媒体库；不添加分组则同步全部已启用的受支持服务器的全部媒体库 |
| 探测并发 | 否 | 并发探测数，默认 1；115 等网盘对请求频率敏感，不建议调大 |
| 探测间隔(ms) | 否 | 相邻两次探测的间隔毫秒，保护网盘请求配额，默认 2000，最小 500 |
| 单文件超时(秒) | 否 | 单个文件探测的超时秒数，留空默认 60 秒 |
| 失败重试间隔(小时) | 否 | 探测失败的文件在该间隔内不重试，避免反复消耗网盘配额，留空默认 2 小时 |
| 备份保留份数 | 否 | 备份目录最多保留的备份 JSON 份数，超出从最旧删除，留空默认 3 份 |
| 消息推送 | 否 | 开启后定时探测完成会推送统计结果 |
| ffprobe 路径（高级） | 否 | 显式指定已有 ffprobe 二进制的绝对路径，见下文「高级用法」 |

### ⭐ ffprobe 探测组件（必读）

探测依赖系统级的 **ffprobe 探测组件**。安装入口全系统只有一个：**系统设置 → 基础配置 → 「ffprobe 探测组件」卡片**，插件不再提供单独的下载源 / 安装配置项。

卡片提供的能力：

| 能力 | 说明 |
|------|------|
| 安装状态 | 显示未安装 / 已安装（版本、来源、安装路径、体积），下载失败时可见最近错误 |
| 一键安装 | 后台下载安装包并解包校验安装，完成后通过消息中心通知 |
| 下载地址 | 展示当前平台对应的下载地址，可一键复制到浏览器手动下载 |
| 手动上传 | 把下载好的安装包（zip / tar.xz / tar.gz / 静态二进制）上传安装 |
| 更新检测 / 一键更新 | 对比最新版本；更新采用原子替换，校验失败自动保留旧版本继续可用 |
| 本地缓存包 | 安装包缓存于配置数据目录（随 config 卷持久化），重建容器或离线环境可直接重装 |
| 重新检测 | 手动刷新安装状态 |

**自动安装**：首次触发探测时若系统尚未安装 ffprobe，会自动调用系统级安装流程装到托管路径（配置数据目录内，随卷持久化）；安装失败时日志与通知会统一引导到设置页的 ffprobe 卡片处理。

### 🔧 高级：指定已有 ffprobe 路径

如果你已在容器 / 主机中自行安装了 ffprobe，可在插件配置的 **ffprobe 路径** 中填写其绝对路径，系统将直接使用它，不再自动下载安装。留空时按「显式配置 → 系统 PATH → 系统托管副本 → 自动安装」的顺序解析。

::: tip 何时需要
只有在自动安装走不通（如网络受限）且你已有可用二进制时才需要填写；绝大多数用户保持留空即可。
:::

## 📖 使用说明

1. 在 **系统设置 → 基础配置 → ffprobe 探测组件** 确认组件已安装（或直接运行，由系统自动安装）；
2. 配置 strm 文件所在的 **扫描目录**（如 `/media/strm/movies`）；
3. 如媒体服务器中已有 strm 的分析结果（如 Emby 神医插件），开启 **同步媒体服务器数据** 可大幅减少网盘探测请求；
4. 点击 **立即探测** 测试一轮，确认成功后按需配置 **定时探测** 与 **消息推送**。

### 🛠 工具栏操作

| 操作 | 说明 |
|------|------|
| 立即探测 | 执行一轮完整探测（同步服务器数据可选 + 扫描 strm + ffprobe 补缺） |
| 同步服务器数据 | 仅从已启用的 Plex / Emby 等同步已有流信息，不执行网盘 ffprobe |
| 备份数据 | 把探测成功的媒体信息备份为 JSON 文件到服务器备份目录 |
| 导入还原 | 导入备份 / 分享的 JSON（按内容 hash 识别，只补缺口不覆盖本地同版本成功数据） |
| 分享下载 | 把探测成功的媒体信息打包为 JSON 直接下载到本机，他人可在任意实例「导入还原」 |
| 清失败记录 | 删除全部探测失败的记录（成功数据保留），删除后需重跑 |
| 清空全部数据 | 删除本插件落库的全部媒体流信息，用于全量重测（需二次确认） |

## 🩺 探测组件不可用时（排障）

- **现象**：探测任务失败，日志 / 通知提示「系统未安装 ffprobe，请到 系统设置 → 基础配置 → ffprobe 探测组件 安装」；[系统体检](/usage/system_settings/system_health.html) 中「ffprobe 探测组件」检查项报异常。
- **处理**：进入设置页 ffprobe 卡片点击 **一键安装**；网络受限环境可 **复制下载地址** 到浏览器下载安装包后 **手动上传**。
- **Alpine 容器注意（glibc / musl）**：Alpine（musl libc）容器中执行动态链接 glibc 的 ffprobe 二进制时，会出现「文件明明存在却提示无法执行 / not found」的报错——这是缺少 glibc 动态链接器导致的二进制不兼容，不是路径填错。建议使用 **静态编译版** ffprobe（无 `.so` 依赖，glibc / musl 容器通吃），下载后通过「手动上传」安装；上传动态链接包会被系统校验拦下并给出诊断提示。
- 仍不行时，可在插件配置 **ffprobe 路径** 中显式指定一个确认可执行的 ffprobe 绝对路径。

## ⚠️ 注意事项

- 探测会真实请求网盘直链，115 等网盘对频率敏感：并发默认 1、间隔默认 2 秒，不建议调大；
- 已探测成功的文件不会重复探测；探测失败的文件在「失败重试间隔」内自动跳过；
- 同步媒体服务器数据时，服务器已有数据优先，ffprobe 只补缺口；
- 「清空全部数据」会删除本插件全部落库信息，重测前请先备份。
