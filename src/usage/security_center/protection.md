# ⚙️ 防护策略

防护策略决定系统「怎么防」：安全等级选档位、防护模式定开关、白名单划豁免、通知定提醒。保存后即时生效，无需重启。

## 🎚️ 安全等级

四档预设，选中即自动套用校准好的参数，**推荐保持「标准」**：

| 等级 | 适用场景 | 封禁口径 |
| --- | --- | --- |
| 宽松 | 仅内网访问，几乎不担心攻击 | 连续输错 5 次暂停 5 分钟，多次重试最长封禁 1 天 |
| **标准（推荐）** | 映射到公网的常规家用场景 | 连续输错 5 次封禁，最长 7 天 |
| 严格 | 公网暴露且曾遭遇攻击 | 连续输错 3 次**永久封禁**（封禁管理可解封） |
| 自定义 | 有明确特殊需求，需自行设定各项参数 |

顶部「恢复为标准等级」可一键回到推荐档。

### 自定义阈值

选择「自定义」后可逐项调整（页面会同步展示当前档位的预设值供参照）：

| 参数 | 含义 |
| --- | --- |
| 失败计数窗口 | 统计登录失败次数的滑动时间窗 |
| 单 IP 阈值 | 一个 IP 在窗口内失败达到该次数即封禁 |
| 用户名 + IP 阈值 | 「某 IP 上试某账号」组合的失败阈值，应不大于单 IP 阈值 |
| 首次封禁时长 | 第一次触发的封禁时长 |
| 最大封禁时长 | 反复触发的指数退避封顶 |
| 升级观察窗口 | 窗口内重复触发才升级封禁时长，跨窗口重新计算 |

::: warning 组合要合理
最大封禁时长应不小于首次封禁时长；用户名 + IP 阈值应不大于单 IP 阈值，否则会出现「试同一个账号反而先封」的怪象。页面在自定义模式下有同样的提醒。
:::

## 🛡️ 防护模式

独立于等级的总体开关：

| 模式 | 行为 |
| --- | --- |
| 强制防护 | 记录并拦截，开箱即防护（默认） |
| 仅监控 | 只记录不封禁——拿不准阈值时先观察一段时间，再开拦截 |
| 关闭 | 关闭全部防护，不建议公网环境使用 |

## ⏳ 数据留存

- **API Key 闲置阈值（天）**：超过该天数的 Key 标记为「长期闲置」，仅提醒不处置，见[凭据治理](./credentials.md)
- **事件保留期（天）**：超过该天数的登录事件与封禁记录自动清理；**生效中的封禁永不删除**

## 🔔 安全通知

| 通知 | 触发时机 |
| --- | --- |
| 新 IP 登录提醒（关键） | 陌生公网 IP 登录成功 |
| 自动封禁提醒（关键） | 登录失败达到阈值触发自动封禁 |
| 凭据处置提醒（关键） | 管理员删除或禁用他人 API Key |
| 手动封禁提醒 | 管理员手动封禁 IP 或网段 |
| 解封提醒 | 单条、批量或全部解封 |
| 配置变更提醒 | 安全等级、阈值或白名单被修改 |

标注「关键」的通知会**绕过消息免打扰立即直发**，其余按常规通知渠道发送。

## ✅ 白名单网段

命中白名单的来源**豁免自动封禁**。填写 IPv4 或 CIDR（如 `192.168.1.0/24`）逐一添加。

::: tip 内网默认已豁免
所有内网私有网段与回环地址默认已豁免，无需手动添加；这里主要加你的**公网出口**（家里宽带、常用办公网），防止自己被误封。
:::

## 🧩 高级配置

页底折叠区，包含两项进阶设置。

### 可信代理网段

使用反向代理（Nginx / NPM / Caddy 等）时，Media Saber 看到的直接连接来源是代理本身。填写代理所在网段后，系统才会采信 `X-Forwarded-For` 等转发头，还原每个请求的真实来源 IP。

::: warning 不配置的后果
反向代理场景不配置可信代理，所有请求来源都会被记成代理的 IP：审计记录失真，自动封禁还可能误伤全体访客。总体态势检测到这种情况会主动提示你「去配置」。
:::

### 自定义阈值

即上文[自定义阈值](#自定义阈值)六项参数，折叠在此处；非自定义等级下只读展示当前预设。

## 🔒 永久封禁

- **自动**：严格档下失败达到阈值即永久封禁（含两步验证码错误——与密码错误同口径计数）。
- **手动**：封禁管理 → 手动封禁，时长默认「永久」，可选 1 小时 / 1 天 / 7 天 / 30 天 / 自定义，并可填写备注。
- **解除**：封禁管理列表对生效记录随时「解封」（单条 / 批量 / 一键清空均可），永久封禁不受保留期清理影响。

::: warning 公网管理提示
管理员会话豁免只覆盖 IP 维度——严格档下你自己从公网连续输错 3 次同样会被永久封禁。建议：公网管理用「标准」档，严格档配合内网管理使用（内网来源不触发自动封禁，可从内网解封自救）。
:::

## 💾 备份提醒

部署备份请包含配置目录下的 `totp.aeskey` 文件（两步验证密钥加密密钥）。该文件丢失后已绑定用户的密钥无法解密，需管理员逐个重置后用户重新绑定。
